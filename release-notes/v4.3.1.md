# IRCC Response Inspector 4.3.1

## 中文
- 修复切换 profile 后继续复用旧申请页面的问题：停止旧查询及取码，在原 Tracker 标签页重新开始流程。
- 申请资料导入/导出独立为强制密码加密文件，只包含 profile。导入前预览并按 ID 合并，保留其他申请及设置；兼容旧版加密备份中的资料。
- 原始查询响应可从设置或申请人进度表头导出，选择明文 JSON 或密码加密文件。确认窗口展示目标申请和响应数量。
- 取消、切换申请或查询批次变化时阻止旧上下文下载并清空密码。支持在设置中本机解密原始数据为 JSON。
- 使用最新一次查询已捕获的响应，不用旧的成功结果替代新查询。已知认证字段会遮盖，History / Security 原始值保留；明文文件分享前仍需自行脱敏。

下载命名的 ZIP（不要选择 Source code），解压后在 Chrome 开发者模式加载。已有安装在原目录更新文件后重新加载扩展，保留原扩展 ID 和本地资料。163 本机程序无需更新（仍为 1.5 / 协议 1）。自动化检查使用虚构数据和本地模拟站，不代表 Chrome 应用商店审核或真实官网全流程认证。

## English
- Fix stale application pages after switching profiles: stop the old query and mail request, then restart the flow in the existing Tracker tab.
- Profile import/export now requires password encryption and contains profiles only. Preview and merge by ID, preserving other profiles and settings. Older encrypted backups supply profiles only.
- Export latest raw query responses from Settings or the applicant-progress header as plain JSON or a password-encrypted file. Confirm the target profile and response count before download.
- Cancel, profile changes and new query contexts prevent stale downloads and clear passwords. Decrypt raw files locally to JSON in Settings.
- Export responses captured in the latest query without substituting an older success. Known authentication fields are redacted; raw History / Security values are retained. Redact personal information before sharing plain files.

Download the named ZIP, not Source code, and load the extracted folder in Chrome Developer mode. Update existing installations in their original folder and reload, preserving the extension ID and local profiles. The 163 helper needs no update (1.5 / protocol 1). Automated checks use synthetic data and a loopback simulator; this is not Chrome Web Store approval or certification of the full live flow.
