# IRCC Response Inspector v4.3.2

## 中文

### 更新须知

- 更新扩展后重新加载。Windows 163 邮箱辅助需要本机程序 **1.6**；请从“设置 → 邮箱连接 → Windows 本机程序”下载安装包，复制新版安装命令运行，完成后检查本机程序。
- 安装命令先核验文件哈希和 PowerShell 执行策略。RemoteSigned 下，解除所选脚本的下载标记需要用户确认；AllSigned、Restricted 或无法读取策略时停止，不自动降低系统策略。当前脚本包没有可信发布者数字签名，签名强制设备需要符合其管理策略的安装方式。

### 主要变化

- 新增“常用链接”：IRCC Tracker、PR Portal、IRCC Portal、新版 Portal、GCKey、IRCC/CBSA/CSIS ATIP、状态指引、处理时间和 Web form。导航紧凑居左；Tracker 入口复用当前窗口的解析器，避免重复标签页。其他外链在新标签页打开，内部切换保留草稿。
- 已启用的 163 辅助在可见控件打开时按需检查版本，不登录邮箱、不解密授权码。正常结果缓存五分钟，失败缓存一分钟；顶部提示直接定位升级卡片，区分未找到、版本不兼容、连接失败和缺少权限。
- 邮箱先筛选有限邮件头，再读取候选正文；保留已识别的共享 Tracker 邮件模板和手动验证码输入。已知不兼容程序不会继续取码。163 程序补充已知旧版凭据清理。
- 续接记录使用字段白名单，原始提交满 24 小时后，在下一次后台启动或邮箱操作时清理；不重发查询或伪造提交时间。
- 捕获及导出进一步清理嵌套 URL、页面参数、片段和已知认证字段。Security 原始业务值保留；导出仍可能包含个人信息，分享前需检查脱敏。
- 统一中英文隐私政策及插件内副本；明确实际存储、认证页标题检查、邮件访问和删除边界。新增可展开使用说明，提醒以 IRCC 官方账户及正式通知为准。History 时间和比较范围使用更准确的标签。
- 发布流程校验政策副本、安装器哈希、ZIP 校验和，并从标签源码重建逐字节比较制品；文本换行标准化。

### 验证与限制

使用合成资料完成 Node 回归、Windows PowerShell 策略模拟、Python helper 单元测试和中英文隔离浏览器检查。未访问真实邮箱或执行真实申请提交；编译启动器专项没有在本次环境完成。自动化测试不能代替真实提供商联调。

Gmail 保持自行配置的开发功能，默认关闭；生产 OAuth 资格、适用审核或例外尚未确认。GitHub 发布不代表 Google、Chrome Web Store、IRCC 或加拿大政府审核、授权或背书。私密反馈入口配置、服务条款和法律适用评估未因本次发布自动完成；不要在公开 Issue 提交敏感资料。公共演示图仍为标明版本的 4.3.1 脱敏示意图。

## English

### Upgrade

Reload the extension after updating. Windows 163 assistance requires helper **1.6**. Download it from Settings → Email connection → Windows helper, copy the new installation command, run it and check the helper afterwards.

The command verifies the file hash and effective PowerShell policy. Under RemoteSigned, removing the selected file's download mark requires explicit confirmation. AllSigned, Restricted and unreadable policy stop installation; no policy is lowered. This script package is unsigned and does not support signature-enforced devices without an approved installation method.

### Changes

- Add a compact, left-aligned Useful links tab covering Tracker, PR/IRCC portals, GCKey, IRCC/CBSA/CSIS ATIP, status guidance, processing times and the web form. Tracker uses the current-window resolver; other destinations open in a new tab. Internal navigation retains drafts.
- Add opt-in, status-only helper compatibility detection, shared probes, bounded caching and header recovery links. Checks never log in to email or decrypt credentials. Distinguish missing, incompatible, unreachable and unauthorized states.
- Filter bounded email headers before reading candidate bodies, retain recognized shared templates and manual entry, block known incompatible helper fetches, and remove known legacy credential copies.
- Allowlist continuation metadata and clean expired records on the next worker start or mailbox operation, 24 hours after the original submission. Do not resubmit or invent request times.
- Remove nested response URL parameters/fragments and known authentication fields at capture/export. Preserve raw Security business values. Exports remain personal data and require review before sharing.
- Synchronize privacy policies, disclose actual access/storage/deletion boundaries, add visible official-information precedence and usage limits, and clarify History/comparison labels.
- Verify policy generation, installer hashes, archive checksums and a byte-identical source rebuild with normalized line endings.

### Validation and limitations

Synthetic Node, Windows policy-mock, Python helper and isolated bilingual browser checks passed. No real mailbox, account or application submission was used; the compiled-launcher integration check was not completed in this environment. These tests do not establish live-provider compatibility.

Gmail remains developer-configured and off by default; production verification or exception eligibility is unconfirmed. GitHub publication is not Google, Web Store or government approval. Private-reporting configuration, service terms and jurisdiction-specific review remain separately documented release considerations. Never post sensitive data in public Issues. Public illustrations remain labeled, redacted 4.3.1 examples.
